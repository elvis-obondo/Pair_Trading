# Master dataset dictionary (HL-MASTER1), version 1 work area — groups built so far

Units: **pair** (6,697,756 events, 20,375 pairs) and **coin** (74,607 coin-vs-market events). Keyed by `event_id` (a row number, stable only within a version). All times UTC.
`t = 0` = `entry_time` + 30 min (the close of the trigger bar). A column is **feature** (uses only information at minutes < t = 0) or **label** (uses the future).
Location while building: `research/datasets/master/work/{pair,coin}/{events,labels,g2,g2b,g3}.parquet`. Nothing here is a released version yet (integrity items 6-9 are pending).

## Keys (events.parquet) — key / geometry at t = 0
| column | definition |
|---|---|
| event_id | row number, 0..N-1; stable only within a version |
| ticker_a, ticker_b | the two legs; coin unit: ticker_b = 'MKT' (the benchmark) |
| entry_time | the 30m bar LABEL T (bar open); the close is observed at T + 30 min |
| bar_index | index of the bar in the 30m panel |
| z, threshold, d | entry z of the adaptive trigger, the threshold it crossed (99th percentile of the pair's previous 96 \|z\|), d = sign(z). **z depends on the order of the legs** (see G2b) |
| beta, alpha, mu, sigma, r2 | frozen entry geometry (96-bar symmetric fit): spread = log A − beta log B − alpha; mu, sigma = rolling mean and sd of the per-bar spread series; r2 = squared correlation of the legs' log levels |
| beta_stab, vol_48, mins_since_trade_a/b | stage A columns (std/\|mean\| of the rolling beta over 336 bars; mean \|30m step\| of the standardised spread over 48 bars; mins since each leg last traded) |
| seg_start_bar, seg_end_bar, bars_into_segment | the NaN-free segment of closes the trigger lives in (end exclusive) and the trigger's index inside it |
| pair_index | pair unit: position in `tradeable_pairs`; coin unit: 100000 + coin column. Key and seed. |
| pair_triggers_true (events only, **future-using, key only, never a feature**), y00..y20 (events_y.npz: label inputs) | |

## G0 Labels (labels.parquet) — **the only columns that use the future**
Path: the 1-minute spread under the FROZEN entry geometry in sigma units, m = 0 is the 1m close labelled T + 29 (= z); move = −(P − z)·sign(z), positive = toward mu. Any NaN minute in the 601 → every label NaN, `label_gap` = 1 (`label_nan_minutes` counts them). Nothing is filled.
| column | definition |
|---|---|
| depth_2h/5h/10h, reach_2h/5h/10h | max of move over minutes 1..H (H = 120/300/600); reach = depth ≥ \|z\| (mu frozen, no stop). depth_10h/reach_10h equal build 3's / build 4's on their rows (asserted) |
| minutes_to_mu | first minute with move ≥ \|z\| (1-based), NaN if none |
| adverse, minutes_to_adverse | move ≤ −\|z\| at some minute in 1..600 (widened by its entry distance), and the first such minute |
| mfe_sigma, mae_sigma | max(0, max move) and max(0, max(−move)) over minutes 1..600 |
| chance_2h/5h/10h | fraction of 50 sign-flip seeds (random ±1 on the 1-minute steps) that reach \|z\| within H; seeded per event from [20261024, pair_index, bar_index]; agrees with build 3's whole-population stream only in distribution |
| fee_sigma_taker, fee_sigma_maker | rate × (1 + \|beta\|) / sigma with rate 0.00099 (0.099% of the position per round trip; legs sized 1 : \|beta\|; position notional fixed at entry) and 0.000495. **Coin unit: "the fee if the benchmark leg could be traded as one instrument at the taker rate — a LOWER BOUND on the real cost, which needs about 200 orders on thin coins"**; its net_* columns carry the same flag |
| outcome_{0p5,1p0,2p0,none}, gross_*, net_*_taker, net_*_maker | stop at s = 0.5/1/2 sigma beyond entry (fires at the first minute with move ≤ −s) or none: outcome +1 mu first / −1 stopped first / 0 neither in 10 h; gross = move at the exit minute **including overshoot, favourable past mu and adverse past the stop** (what a one-minute monitor realises), or move[600] if neither; net = gross − fee_sigma |
| label_gap, label_nan_minutes | 1 when any of the 601 minutes is NaN (archive hole or missing minute); 27,049 pair events (0.40%), 640 coin events (0.86%) |

## G2 Hedge quality (g2.parquet) — feature, windows end at the trigger bar / the 1m bar T + 29
Expected direction (recorded, not tested): r2 higher → reverts more (OKX evidence); all others two-sided.
| column | definition and rule |
|---|---|
| r2_2d, r2_7d | squared Pearson correlation of the log-price LEVELS over 96 / 336 bars (r2_2d = the event's r2, asserted) |
| corr_30m_2d, corr_30m_7d | correlation of the legs' 30m log returns over 96 / 336 bars |
| corr_1m_24h, n_1m_24h, both_traded_share_24h | correlation of 1-minute returns over the 1,440 minutes ending with the 1m bar T + 29; a return is used only when both closes of both legs exist; flat (carried) minutes are zero returns (the real last price); NaN if < 1,000 usable minutes; share of the 1,440 minutes in which both legs traded (mins_since_trade = 0; a missing row counts as not traded). Coin unit: the benchmark minute path is the bridged 1m level (linear correction inside a bar using that bar's end level, observed at the bar close = t0 for the trigger bar: every minute is known at t0); both_traded_share = the coin's own share |
| beta, abs_beta, sign_beta, neutrality | entry beta (vol-matched sd(a)/sd(b) signed by the covariance); neutrality = \|1 − \|beta\|\| / (1 + \|beta\|). beta and abs_beta become reciprocals if the legs are swapped; neutrality, r2, corr are leg-symmetric |
| beta_stab, beta_chg_24h, beta_chg_7d | std/\|mean\| of the rolling beta over 336 bars; beta[i] − beta[i−48], beta[i] − beta[i−336] (NaN before the segment's first finite beta). Not exactly swap-symmetric (not asserted) |
| vol_ratio_2d, vol_ratio_7d | sd of A's 30m returns / sd of B's, 96 / 336 bars (ddof 1); reciprocal under a swap |
| crossings_7d, halflife_h, phi_7d | **gap-fill (A):** on the standardised spread w under the FROZEN entry geometry (mu, beta, alpha, sigma at i applied back over 336 bars; not a per-bar rolling mean): sign changes of w; AR(1) OLS slope phi of w on its lag; half-life −ln2/ln(phi) × 0.5 hours if 0 < phi < 1 else NaN. NaN for triggers younger than 336 bars (coin unit only, 1.04%). crossings and sandwich are orientation-dependent (swapped vs original: correlation 0.83 and 0.78); phi, half-life (it follows phi), vratio and vol_slope agree between orientations (correlation 1.000, median difference 0) |
| vratio, vol_slope, sandwich | envfeat's: sd(steps)/sd(levels) of the sign-folded w over 96 bars × 3.396899; sd of the last 16 steps / the 32 steps before; mean over 96 bars of (the sign-folded spread's within-bar maximum from the legs' 30m high/low − its close) / sigma. **Coin unit: sandwich has no analogue (no high/low for a synthetic level): NaN** |
| g2_nan_1m, seg_bars | flag that corr_1m_24h is NaN; bars into the segment (short history visible) |

## G2b Symmetric z (g2b.parquet) — feature, orientation-proof
Bar i's own beta_i and alpha_i applied to the WHOLE 96-bar window: `sigma_sym` = std (ddof 1) of (a_j − beta_i b_j) over the window; `z_sym` = (a_i − beta_i b_i − alpha_i) / sigma_sym; `z_ratio` = \|z_sym\| / \|z\|; `threshold_sym` = 99th percentile of \|z_sym\| over bars i−96..i−1; `trig_sym` = 1 if \|z_sym,i\| > threshold_sym,i and the previous bar was not above its own threshold (0 otherwise, NaN if not finite). Swap: z_sym' = −sign(beta) z_sym, sigma_sym' = sigma_sym/\|beta\|, trig_sym' = trig_sym (asserted). Coin unit: leg B = the benchmark level. Window handling: the 96-bar window needs 96 bars of the segment, so z_sym is NaN for the first 95 bars and threshold_sym (96 prior finite z_sym) from the 192nd bar on; no event falls there (pair triggers are at segment bar ≥ 335, coin triggers ≥ 191), shorter windows are never used.

## G3 History (g3.parquet) — feature; reads past LABELS, so the resolution rule matters
Previous event j of the same series (pair; coin for the coin unit) is **resolved** at t0 iff T_i − T_j ≥ 600 min (its outcome path ends with the 1m close at T_j + 630 ≤ t0; the boundary counts) AND label_gap_j = 0. Unresolved events count only in n_prev_triggers, days_since_last_trigger, triggers_last_7d (their times are known).
| column | definition |
|---|---|
| n_prev_triggers, n_prev_resolved | earlier events; resolved ones |
| prev_reach_raw, prev_reach_shrunk, global_reach_asof | mean reach_10h of resolved ones; (sum + 20 g)/(n + 20) with g = the as-of global rate (all resolved events of the unit at t0); g itself |
| last1_reach .. last5_reach, last5_mean | reach_10h of the last five resolved events, MOST RECENT FIRST; mean of those available |
| days_since_last_trigger, triggers_last_7d | days since the previous event (resolved or not); events in the last 7 days |
| prev_mean_minutes_to_mu | mean minutes_to_mu of resolved events that reached mu |
| a_/b_coin_n_resolved, _coin_reach_raw, _coin_reach_shrunk, coin_reach_shrunk_diff (pair unit) | the legs' coin-vs-market history from the COIN unit, same rule (g = the coin unit's as-of rate); a − b of the shrunk rates |

## Orientation (planner ruling 2026-10-24 on integrity item 3)
The adaptive trigger's z, and every column built on the rolling spread series, depend on which coin is leg A (the rolling spread uses each bar's own beta, so swapping the legs gives a different series). Required and asserted exactly: the leg-pair statistics (r2_2d/7d, corr_30m, corr_1m, neutrality, traded share; beta, abs_beta and the vol ratios as reciprocals) and the whole G2b family (z_sym' = −sign(beta) z_sym, sigma_sym' = sigma_sym/|beta|, trig_sym' = trig_sym).
**Orientation-dependent, measured on 1,000 real events (master_tests_g2.log):** the entry z (|z'|/|z| quantiles 5/25/50/75/95% = 0.24 / 0.65 / 0.88 / 1.04 / 1.35; correlation of z with the sign-corrected z' 0.922), crossings_7d (correlation between orientations 0.830, median |difference| 2), sandwich (0.784, median |difference| 0.154). phi_7d, halflife_h, vratio and vol_slope agree between orientations (correlation 1.000, median difference 0). Later groups: flow and wallet columns that use d = sign(z) and the leg weights are orientation-dependent through z; their symmetry is tested on the leg-level building blocks with d held fixed, and the net columns' asymmetry is reported the same way.

## G6 Wallets (g6_a, g6_b, g6_net parquet) — feature; see research/dataset/master_g6.py and master_g6_run.py
Built from build 5's wallet tables: T1 (wallet x coin x 5-minute bin, taker/absorbed USD) and T2 (wallet x day: volume, closed PnL, fills, own liquidations). Per LEG (a, b) and, for shares and means only, net (weighted with G5's w_a).
- **Window.** 30 / 60 / 360 / 1440 minutes ending at t0, whole 5-minute bins strictly before t0. A window that reaches before 2025-05-25 14:35 or touches a missing minute gives NaN.
- **Push side.** The side the dislocation pushes: taker buys if s > 0, sells if s < 0 (T1, on-book, one taker per trade).
- **Two populations.** ALL wallets, and HUMAN = all wallets except the four HLP liquidator wallets and the vault leader 0xdfc24b…. Vault and leader labels come from the planner brief of 2026-10-24 (the user's confirmation). Both versions are stored; the vaults are never dropped.
- **Per population and window (suffix _all / _human):** top1, top3 (share of the pushing notional from the largest 1 / 3 wallets), hhi (sum of squared wallet shares), nw (wallets pushing), pers (share from the coin's 10 largest taker wallets by the trailing 7 UTC days ending before the trigger's day; needs >= 3 days), twap (the population's TWAP USD over its taker USD; NaN before 2025-07-27 08:00), skill_mean (notional-weighted mean skill), **skill_cov** (share of pushing notional from wallets whose skill is defined; read skill_mean with it), bot and topd (shares from the bottom and top decile by skill), prior_forced (share from wallets with an own liquidation in the prior 30 days), push_total (pushing USD).
- **Skill.** From T2 days strictly before the trigger's day: trailing 30-day closed PnL / volume x n_fills / (n_fills + 5000). NaN with fewer than 5 active days. Deciles are over wallets active the day before.
- **Not per population:** vault_push_share (vault and leader pushing USD / push_total_all) and vault_absorb_share (the four vaults' absorbed USD on the side opposite the push / push_total_all).
- **NaN rule.** push_total = 0 gives NaN shares and nw = 0 (window valid). The first 30 days of skill are NaN.
- **vault_push_share is near-constant.** Median 0 and 95th percentile 0 on the trigger legs: vaults almost never take the pushing side. vault_absorb_ratio is unbounded (>= 0, can exceed 1); vault_absorb_share = absorbed / (absorbed + push_total_all) is bounded in [0, 1] and is the default.
- **Net columns.** Only the shares and means are netted with w_a. Counts (nw) and USD (push_total) exist per leg only.
- **Caveats.** One entity can run many wallets, so concentration is a lower bound. Skill is noisy and heavy-tailed. The pair columns inherit the leg orientation (d held fixed; swap-tested on the building blocks only).
- **Tests.** master_tests_g6.py: poison (T1 rows at or after the trigger bin and T2 days from the trigger's day overwritten or removed), independent recomputation in plain pandas, invariants (shares in [0,1], push_total_all >= push_total_human, nw_all >= nw_human, vault_push_share = 1 - push_total_human / push_total_all).

## G8 Order book (g8.parquet) — feature; see research/hyperliquid/build8_l2.py (per coin-minute table) and research/dataset/master_g8.py (event stage)
Source: s3://hyperliquid-archive/market_data/{YYYYMMDD}/{H}/l2Book/{COIN}.lz4 (requester pays), snapshots every ~0.55 s, 20 levels per side, bids = levels[0], asks = levels[1]. Extracted on EC2 us-east-2 (the account's SCP denies EC2 in us-east-1).
- **Coin-minute row.** Label m = floor(exchange ms / 60000) from raw.data.time. The row is the snapshot with the MINIMUM exchange time in minute m. One row per (coin, minute) per UTC day; a minute that appears in two hour files (a snapshot stamped just before the hour sits in the next hour's file) keeps the earlier snapshot, and the duplicates removed are counted per day in the run log. Rows outside the day are dropped (the day's own files carry those minutes). Harmless consequence: a snapshot of minute 23:59 on day D that sits in D+1's 00h file is never read by day D; D's own 23h file still supplies that minute, at worst a few hundred ms later.
- **As-of rule.** t0 = T + 30 min. The row used is the one labelled t0 - 1 minute: the first snapshot with exchange time in [t0 - 60 s, t0). Never the row labelled t0. A missing row gives NaN; nothing is carried from an older minute. snapshot_age_s = t0 - exchange time of the snapshot used = 60 - snap_off_s.
- **Per leg (a_, b_; coin unit: a only):** mid; spread_bp = (best ask - best bid) / mid x 1e4; bid_d{10,25,50} / ask_d{10,25,50} = sum of price x size of the levels within that many bp of mid, per side, in USD; trunc_{bid,ask}_{10,25,50} = 1 when the 20th stored level is still inside the band (the depth is then a lower bound); imb_{b} = (bid_d - ask_d) / (bid_d + ask_d) at each band; slip_{buy,sell}_1k = (VWAP of the walked levels - mid) / mid x 1e4 for buys and (mid - VWAP) / mid x 1e4 for sells, NaN when the 20 levels hold less than $1,000 (no position will exceed $1k; user 2026-10-25, 10k/50k slippage columns removed); book_reach_{bid,ask}_bp = bp from mid to the 20th stored level; crossed = 1 when best bid >= best ask (every other quantity of that row is NaN); snapshot_age_s.
- **Relative depth.** rel_{bid,ask}_d{b} = depth / its median over the previous 336 half-hour cutoff rows (not including the current one; at least 144 finite; NaN if the median is 0).
- **Changes.** chg1h_X, chg6h_X = X at the cutoff minus X two / twelve cutoffs earlier, for X in spread_bp, bid_d10, ask_d10, imb_10, slip_buy_1k, slip_sell_1k (NaN if either row is missing).
- **Decision sources.** book_reach_{bid,ask}_bp: user decision 2026-10-25 via the planner (a continuous measure of the truncation that the trunc_* flags show). slip_buy_1k / slip_sell_1k: user decision 2026-10-25 via the planner (no position larger than $1k); the 10k / 50k versions were removed.
- **Pair.** a_*, b_* and d_X = a_X - b_X for the numeric columns (not mid, crossed, trunc_*, snapshot_age_s).
- **NaN rules and data limits.** Missing hours stay NaN. Empty book side (delisted coins keep files with empty sides) gives NaN. Slippage beyond the 20 levels is NaN: the pilot's $10k and $50k versions were NaN on 3-17% and 36-74% of rows; the $1k version is measured in the full run's coverage table. Depth at 25 and 50 bp is truncated (a lower bound) on 26-40% and 52-69% of rows: read it with trunc_* and book_reach. The snapshot rate falls from about 6,500 to about 670 per coin-hour by 2026-09-15 (median gap 5.4 s, first snapshot a median 2.7 s into the minute), so the as-of row is staler there: read it with snapshot_age_s. The snapshot rate by month is in the run's coverage table.

## Price files: 30m bars and 1m bars
30m bars cover whole windows inside the coin's life; the first partial bar of a listing is excluded by build 2's rule (H = date_range(life[0].ceil("30min"), life[-1] - 29 min)), while the 1m file has rows inside it (38 coin listings; the 1m close labelled T + 29 exists, the 30m bar does not). Wherever both exist the closes are identical. The coin unit's benchmark (and the 30m panel) follow the 30m files, so a coin joins the cross-section at its first whole bar. Whether to include the partial bar is a user decision; nothing was changed.

## Known limitations of version 1 (with counts)
1. **Coin unit, trigger-bar bridging (user decision 2026-10-26, left as is).** The coin path's m = 0 point is bridged inside the trigger bar like every other point, so one missing one-minute index return among that bar's 30 makes the path NaN and label_gap = 1, although z and the level are known exactly. Of the 640 coin events stored with label_gap = 1 (0.86% of 74,607), 19 have a NaN only at m = 0 and 4 more at m = 0 and later (23 in all with NaN at m = 0).
2. **Coin unit, 38 late listings (user decision 2026-10-26, left as is).** The 30m bar files omit a coin's first partial bar (build 2's rule); the coin joins the benchmark cross-section at its first whole bar. 38 coin-bars out of about 5.0 million are finite in the 1m file and absent in the 30m file; closes are identical wherever both exist.
3. **Coin unit fees are a lower bound** (the benchmark leg is a synthetic index).
4. **Orientation.** For pairs, z, crossings, sandwich and the other z/spread-based columns depend on which leg is A (|z'|/|z| quantiles 0.24 / 0.65 / 0.88 / 1.04 / 1.35); G2b (sigma_sym, z_sym, z_ratio, threshold_sym, trig_sym) is exactly symmetric, and so are the leg-pair statistics. Flow and wallet columns are tested on building blocks with the push direction held fixed.
5. **Label gaps:** 0.40% of pair events (27,049) and 0.86% of coin events (640) have label_gap = 1; labels are NaN there.
6. **Non-stationary base rate.** The chance baseline fell from about 0.47 to 0.50 in 2025 to 0.40 by 2026-09 while the reach rate stayed 0.31 to 0.35. Read any column's relation to reach_10h by month, not pooled.
7. **Order book:** 20 levels per side only, so depth at 25 and 50 bp is a lower bound on 26 to 40% and 52 to 69% of rows (trunc_* flags, book_reach_*_bp); 1.02 million duplicate (coin, minute) rows from hour-boundary spillover were resolved (earliest exchange time kept) and 3,642 rows lying outside their day were dropped (their own day's files carry those minutes); rel_* (needs 144 finite cutoff rows of the previous 336) is NaN on 11% of rows and chg1h / chg6h wherever either row is missing.
8. **Sparse columns:** forced-liquidation timing columns (mins_since_forced_any NaN 72%, mins_since_forced_spike 93%), ps_mins_since_big_step (31%), vault_push_share (median 0, near-constant), twap columns before 2025-07-27 08:00.
9. **Test sizes (explicit waivers, NUMBERS [HL-WAIVERS]).** G6 poison ran at 400 legs; G8 poison ran at 36 (coin, cutoff) trials (12 coins x 3 cutoffs) plus a deliberately broken variant that it catches in 34 of 36; both accepted by the user (2026-10-25 and 2026-10-26). Swap-test scope was narrowed by the planner (exact symmetry for leg-pair statistics and the G2b family; the rest measured and labelled).
10. **Deferred: Part Z (the side-by-side) moves to after release** (user, 2026-10-26) as the first post-v1 task. The column report code (master_colreport.py) and its outputs under work/{unit}/reports/ were produced before that decision and are not part of the v1 release report.
11. **Code identity.** The dataset code is not committed; its identity rests on the sha256 of every code file in MANIFEST.json (see the freeze).
